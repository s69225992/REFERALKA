# Рефералка — единый проект (Next.js + Vercel)

Реферальная программа для водителей таксопарка на **одном стеке**: кабинет, API,
расчёт и выплаты через Yandex Fleet API, еженедельный автозапуск через Vercel Cron.

**Логика:** водитель приводит водителя → парк получает комиссию (~3%) → реферер
пожизненно получает её долю (по умолчанию **1/3**, т.е. ~1% от оборота реферала).

## Стек

- **Next.js 14** (App Router) — кабинет + API-роуты, деплой на Vercel
- **Prisma + PostgreSQL** (Neon или Supabase) — база
- **Vercel Cron** — еженедельный расчёт и выплаты
- **Yandex Fleet API** — источник комиссии и канал выплат

## Структура

```
prisma/schema.prisma        5 таблиц: drivers, referrals, commission_snapshots,
                            referral_accruals, payout_log
src/lib/
  config.ts                 конфиг из env
  prisma.ts                 клиент Prisma (singleton)
  fleet.ts                  клиент Yandex Fleet API
  money.ts                  денежные расчёты в копейках (без ошибок float)
  services/
    sync.ts                 синхронизация водителей
    calculation.ts          расчёт доли 1/3 + защита от дублей (idempotencyKey)
    payout.ts               выплаты (X-Idempotency-Token)
    cycle.ts                полный цикл: синк → расчёт → выплата
src/app/
  page.tsx                  лендинг с ссылками
  admin/page.tsx            админ-кабинет (сводка, начисления)
  driver/[id]/page.tsx      личный кабинет водителя
  api/
    cron/weekly             еженедельный cron (Vercel Cron)
    admin/overview          сводка (защита ADMIN_TOKEN)
    admin/run-cycle         ручной запуск цикла (защита ADMIN_TOKEN)
    drivers/[id]/...         код, рефералы, начисления, привязка реферера
scripts/run-cycle.ts        ручной прогон из терминала
vercel.json                 расписание Cron (пн 00:00 UTC = 03:00 МСК)
```

## Локальный запуск

```bash
npm install
cp .env.example .env         # заполнить DATABASE_URL и FLEET_API_KEY (секрет)
npx prisma db push           # создать таблицы в базе
npm run dev                  # http://localhost:3000
```

> Примечание: `prisma generate` скачивает движок при установке — нужен доступ
> в интернет (на Vercel и локально это работает; в изолированных песочницах может
> блокироваться).

### Шаг 1. Найти категории «комиссии парка»

```bash
npx tsx scripts/run-cycle.ts --categories
```

Выведет id и названия категорий транзакций. Найди те, что соответствуют комиссии
парка, и впиши в `PARK_COMMISSION_CATEGORY_IDS` в `.env` (через запятую). От этого
зависит, с какой суммы считается 1/3.

### Шаг 2. Тестовый прогон за период

```bash
npx tsx scripts/run-cycle.ts 2026-08-01 2026-08-08
```

Синхронизирует водителей, посчитает начисления, выплатит pending. На пилоте начни
с 1–2 тестовых пар и сверь суммы вручную, прежде чем включать всех.

## Самый простой API-тест (БЕЗ npm install и БЕЗ базы)

Файл `report-standalone.mjs` — автономный скрипт на чистом Node 18+ (встроенный fetch),
никаких зависимостей ставить не надо. Единственное действие — подставить секрет ключа:

```bash
# показать категории и разбивку (найти "комиссию парка"):
FLEET_API_KEY=<секрет_ключа> node report-standalone.mjs 2026-08-01 2026-08-08

# когда знаешь категорию комиссии парка — задать её и получить итог:
FLEET_API_KEY=<секрет> PARK_COMMISSION_CATEGORY_IDS=<id_категории> \
  node report-standalone.mjs 2026-08-01 2026-08-08
```

`FLEET_CLIENT_ID` (422835) и `FLEET_PARK_ID` уже вшиты дефолтами. Скрипт проверен на
мок-сервере — логика и суммы корректны; в бою отличается только реальный ключ.
Вывод «Комиссия парка (все активные)» сверь со своим доходом парка.

## Быстрый тест-сверка (1% по всем активным водителям, БЕЗ базы)

Самый быстрый способ убедиться, что API отдаёт верные данные и математика сходится,
ещё до настройки базы и рефералки. Нужны только переменные Fleet API в `.env`.

```bash
# 1) какие категории есть (найти "комиссию парка")
npx tsx scripts/report.ts --categories
# 2) вписать нужные id в PARK_COMMISSION_CATEGORY_IDS в .env, затем:
npx tsx scripts/report.ts 2026-08-01 2026-08-08
```

Отчёт выведет по каждому активному водителю комиссию парка и её долю (1%/33%), плюс
ИТОГО. Строку «Комиссия парка (все активные)» сверь со своим реальным доходом парка.
Если категория ещё не задана — отчёт покажет разбивку по всем категориям, чтобы ты
нашёл нужную.

Тот же отчёт доступен на Vercel как эндпоинт (без базы):
`/api/admin/test-report?token=<ADMIN_TOKEN>&from=2026-08-01&to=2026-08-08`

## Деплой на Vercel

1. Залей проект в Git и импортируй в Vercel.
2. Заведи PostgreSQL: **Neon** или **Supabase** (можно прямо из вкладки Storage в Vercel).
3. В Vercel → Settings → Environment Variables пропиши всё из `.env.example`
   (особенно `FLEET_API_KEY`, `DATABASE_URL`, `CRON_SECRET`, `ADMIN_TOKEN`).
4. Деплой. `vercel.json` уже настроит Cron `/api/cron/weekly` на понедельник 03:00 МСК.
   Vercel сам подставляет `CRON_SECRET` в заголовок Authorization при вызове cron.
5. Первый раз создай таблицы: локально `npx prisma db push` на прод-базу,
   либо добавь этот шаг в пайплайн.

## Защита от двойных выплат

`idempotencyKey = ref_{реферер}_{реферал}_{период}` — уникальный индекс в БД +
тот же ключ уходит в Яндекс как `X-Idempotency-Token`. Повторный прогон того же
периода не создаст новое начисление и не выплатит дважды.

## Безопасность (доделать перед боем)

- **Админ-страница `/admin`** в MVP открыта и читает БД напрямую — закрой её
  авторизацией (Vercel middleware + пароль/Auth) перед публикацией.
- **Личный кабинет `/driver/[id]`** в MVP по id из URL — добавь вход водителя
  (телефон + SMS) и выдачу токена, проверяй его в middleware.
- API-роуты `admin/*` и `cron/*` уже защищены токенами из env.
- Секрет Fleet API — только в переменных окружения Vercel, никогда в коде/гите.

## Оговорки

- Точные имена полей ответов Fleet API сверь с офиц. документацией (кнопка
  «Документация» в разделе API диспетчерской) — парсинг оборонительный, но версии меняются.
- `PAYOUT_CATEGORY_ID` — категория, под которой начисляется бонус; при необходимости
  заведи подходящую в диспетчерской.
- Для больших парков (тысячи водителей) недельный cron дроби на пачки, чтобы уложиться
  в лимит времени serverless-функции (`maxDuration`).
- В проде используй миграции Prisma (`prisma migrate`) вместо `db push`.
